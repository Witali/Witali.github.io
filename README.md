# Погромист — личный дневник разработки

Статический блог для GitHub Pages. Предисловие постоянно находится над лентой, первые три записи видны сразу, остальные загружаются порциями по три при прокрутке. Есть кнопка загрузки, полный архив без JavaScript и RSS/Atom. Проекты находятся на отдельной странице `projects.html` с компактной шапкой.

## Запуск

Нужен Node.js 22 или новее.

```powershell
npm ci
npm run dev
```

Откройте http://127.0.0.1:4173/. После изменения исходников перезапустите сервер. Проверки: `npm test`; сборка: `npm run build`. Готовый сайт находится в `dist/`, эта папка не коммитится.

## Новая запись

Создайте файл в `content/posts/`. Имя обязательно начинается с даты: `YYYY-MM-DD-short-name.md`. Название после даты пишется латиницей через дефис. Файлы естественно сортируются по имени, на сайте порядок обратный.

```markdown
---
title: Что получилось сегодня
date: '2026-10-26'
tags: [MicroMusic]
sources:
  - label: Изменения в проекте
    url: https://github.com/Witali/MicroMusic
---
Закончил новую часть проекта.
Проверил её в браузере и на плате.
```

Максимум десять предложений в тексте, заголовок и ссылки на источники в лимит не входят. Дата в метаданных должна совпадать с именем файла. Будущие записи не публикуются до наступления их дня в `Europe/Budapest`; для появления потребуется новая сборка сайта.

Для предисловия редактируйте `content/intro.md`; иллюстрация хранится в `assets/workbench.png`; название, автор и адрес сайта — в `site.config.json`.

## Проекты и видео

Каждый проект хранится отдельно в `content/projects/*.md`. В метаданных задаются `title`, `category`, числовой `order`, массив `links`; ниже пишется краткое описание.

В посты и проекты можно добавить `videos` со ссылками на YouTube:

```yaml
videos:
  - label: Видео о проекте
    url: https://youtu.be/WqFaOTUdEe0
    published: '2026-10-24'
```

В дневнике видео добавляется только в запись за день его публикации: поле `published` должно совпадать с датой поста. Один ролик не повторяется в разных записях; если в этот день видео не выходило, ссылок на видео в посте нет. Сборка проверяет даты и повторы, в том числе для коротких и полных YouTube-ссылок. В карточках проектов можно хранить все соответствующие видео без привязки к дню и без поля `published`.

## GitHub Pages

**Перед публикацией необходимо явное одобрение пользователя после просмотра готового сайта.** Это правило сохранено в `AGENTS.md` и распространяется на push, запускающий deployment. Пока одобрения нет, работайте локально.

Приватные GitHub- и Bitbucket-проекты и сведения о них исключены без отдельного явного разрешения. Проверка `npm run check:public` сравнивает ссылки со списком уже подтверждённых публичных источников в `content/public-sources.json`. Она работает локально без сетевых запросов и также выполняется при сборке. Новые источники добавляйте в список после проверки публичности; для Bitbucket проверяйте `is_private: false` через API без авторизации. Перед публикацией подтвердите публичность заново и проверьте всю отправляемую историю Git.

Workflow `.github/workflows/pages.yml` проверяет и собирает сайт после push в `main`, затем публикует папку `dist/`. В репозитории выберите **Settings → Pages → Source → GitHub Actions**. Pull request запускает только проверку и сборку.

Для репозитория `Witali.github.io` адрес будет `https://witali.github.io/`. Если использовать другой репозиторий, GitHub Actions автоматически подставит нужный префикс пути. При локальной проверке такого размещения передайте `SITE_BASE_PATH=/blog` и `SITE_ORIGIN=https://witali.github.io` при сборке.

## Google Analytics

Публичный идентификатор потока `G-...` хранится в переменной репозитория GitHub Actions `GA4_MEASUREMENT_ID` (**Settings → Secrets and variables → Actions → Variables**), отдельно от исходников. Сборка подставляет его в HTML, поэтому в опубликованной странице он виден посетителю. Это штатный публичный идентификатор, а не ключ доступа; API secrets и другие учётные данные для такого подключения не нужны.

Если переменная не задана, счётчик и его элементы управления не добавляются. Для pull request переменная не передаётся. Локальный предпросмотр не загружает Google Analytics даже при заданном ID. Новый ID проверяется по формату; ошибочные значения не выводятся в журнал.

Код Google загружается после согласия посетителя. Отклонение сохраняется наравне с разрешением; выбор действует 180 дней и меняется кнопкой «Настройки аналитики» в подвале. При отзыве согласия cookies этого счётчика удаляются, страница перезагружается без Google Analytics. Рекламная персонализация и Google Signals отключены; параметры и фрагмент URL страницы не передаются, от источника перехода остаётся только origin. Описание обработки данных находится на `privacy.html`.

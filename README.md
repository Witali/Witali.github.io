# Погромист — личный дневник разработки

Статический блог для GitHub Pages. Предисловие постоянно находится над лентой, первые три записи видны сразу, остальные загружаются порциями по три при прокрутке. Есть кнопка загрузки, полный архив без JavaScript и RSS/Atom.

## Запуск

Нужен Node.js 22 или новее.

```powershell
npm ci
npm run dev
```

Откройте http://127.0.0.1:4173/. После изменения исходников перезапустите сервер. Проверки: `npm test`; сборка: `npm run build`. Готовый сайт находится в `dist/`, эта папка не коммитится.

## Новая запись

Создайте файл в `content/posts/`. Имя обязательно начинается с даты: `YYYY-MM-DD-short-name.md`. Название после даты пишется латиницей через дефис. Файлы естественно сортируются по имени, на сайте порядок обратный.

```markdown
---
title: Что получилось сегодня
date: '2026-10-26'
tags: [MicroMusic]
sources:
  - label: Изменения в проекте
    url: https://github.com/Witali/MicroMusic
---
Закончил новую часть проекта.
Проверил её в браузере и на плате.
```

Максимум десять предложений в тексте, заголовок и ссылки на источники в лимит не входят. Дата в метаданных должна совпадать с именем файла. Будущие записи не публикуются до наступления их дня в `Europe/Budapest`; для появления потребуется новая сборка сайта.

Для предисловия редактируйте `content/intro.md`; иллюстрация хранится в `assets/workbench.png`; название, автор и адрес сайта — в `site.config.json`.

## GitHub Pages

Workflow `.github/workflows/pages.yml` проверяет и собирает сайт после push в `main`, затем публикует папку `dist/`. В репозитории выберите **Settings → Pages → Source → GitHub Actions**. Pull request запускает только проверку и сборку.

Для репозитория `Witali.github.io` адрес будет `https://witali.github.io/`. Если использовать другой репозиторий, GitHub Actions автоматически подставит нужный префикс пути. При локальной проверке такого размещения передайте `SITE_BASE_PATH=/blog` и `SITE_ORIGIN=https://witali.github.io` при сборке.

## Первые записи

Записи за 18–25 октября 2026 года основаны на подтверждённых публичных изменениях проектов. Ссылки «По следам работы» ведут на соответствующие изменения. Непубличные идеи и обсуждения из личных чатов не используются для публикаций без отдельного явного разрешения.
